# Русский бренд — дизайн-промпт и gstack-пайплайн

Два артефакта: (1) исходный дизайн-промпт, по которому делали оформление раздела,
(2) пайплайн под gstack — какие агенты/скиллы задействовать в следующий раз.

---

## 1. Дизайн-промпт («Русский бренд»)

Самодостаточный бриф — можно копировать целиком:

```
Спроектируй брендированное оформление рубрики «Русский бренд» — раздел внутри СМИ2
(референс-страница smi2.ru/publisher/3058). Медиа о российских брендах: истории
создателей, интервью, обзоры, новости.

СТЕК: Astro 6 + Tailwind CSS v4 + MDX. Деплой на GitHub Pages под base /russkiy-brand.

КОНЦЕПЦИЯ: «русская редакционная роскошь», НЕ сувенирный фолк. Смешай три культурных
слоя ПО ФУНКЦИИ, а не декоративно:
  • 60% — editorial/digital (основа: чистая редакционная сетка, воздух, типографика)
  • 25% — имперское (композиция: симметрия, рамки, матовое типографское золото, статус)
  • 15% — советское (акцент: конструктивистская геометрия, плакатный красный — скупо)

Мудборд-коды: вологодское кружево, красный фолк-силуэт, конструктивистский шрифт
(«УТРО»), резные деревянные вертикальные панели.
ЗАПРЕЩЕНО: матрёшки, балалайки, хохлома, буквальный лубок.

ПАЛИТРА: молочный крем + чернила/графит + акцент бордо + матовое (типографское) золото;
красный — только точечно.
ШРИФТЫ: Cormorant Garamond (serif-заголовки) + Inter (UI) + Oswald
(конструктивистские кондансед-лейблы/бейджи).

ТРЕБОВАНИЯ:
  1. Три mood-направления вживую через html[data-dir="editorial|imperial|soviet"],
     переопределяющие только CSS-токены Tailwind в рантайме. Переключатель + localStorage.
     Базовое направление — editorial (синтез 60/25/15).
  2. Декоративный кит: боковые ажурные поля (кружево) видны при ≥1280px, на мобильном
     схлопываются в ажурные кромки шапки/футера. Розетка, клеймо-маркер, фестоны.
  3. Шапка — титульная плашка (nameplate) с маркой + дескриптором.
  4. Карточки — угловые скобки + конструктивистские бейджи рубрик.
  5. Логотип-марка: монолитная геометрическая «Р» как клеймо мастера в скруглённом
     квадрате + baseline-tick, одноцветная (currentColor), масштабируется до аватара.
  6. Стайлборд + UI-kit на отдельной странице /styleguide: палитра, типографика,
     декор, бейджи, карточки, ссылки — на одном экране.

ДОСТУПНОСТЬ: focus-visible, prefers-reduced-motion, тач-таргеты ≥44px,
уникальные id SVG-паттернов.
```

Эта ДНК дала: `data-dir`-переключатель, `Ornament.astro` / `SideRails.astro`,
брендовые классы в `global.css`, страницу `/styleguide`, клеймо-логотип.

## 2. Пайплайн под gstack

Сначала — замысел и требования, потом дизайн-система и варианты, ревью плана глазами
дизайнера, реализация и финальная полировка. Дизайн-скиллы стоят в правильных точках.

| # | Фаза | Скилл | Что делает |
|---|------|-------|-----------|
| 0 | Замысел | `superpowers:brainstorming` | Вытянуть intent/требования до кода (обязательно перед планом) |
| 1 | Дизайн-система | **`/design-consultation`** | Изучает продукт+ландшафт, предлагает целостную систему (эстетика, шрифты, цвет, сетка, motion) + font/color превью |
| 2 | Разведка вариантов | **`/design-shotgun`** | Генерит несколько вариантов интерфейса, открывает доску сравнения, собирает структурный фидбэк |
| 3 | План | `superpowers:writing-plans` | Пишем план реализации по выбранному варианту |
| 4 | Ревью плана | **`/plan-design-review`** | Продуктовый дизайнер ищет недостающие решения, предлагает добавить, помогает принять важные |
|   | (доп.) | `/plan-ceo-review`, `/plan-eng-review` | CEO/eng-оптика на тот же план |
| 5 | Реализация | **`/design-html`** | Превращает утверждённый макет в адаптивный код (React/Svelte/Vue; для Astro — как основу разметки/CSS) |
| 6 | Аудит | **`/design-review`** | Визуальный аудит + финальная полировка (AI-slop, отступы, иерархия, a11y) |
| 7 | QA | `/qa` или `/browse` | Прогон в headless-браузере, ловим баги |
| 8 | Отгрузка | `/ship` → `/land-and-deploy` → `/canary` | PR, деплой, пост-деплой мониторинг |

### Быстрый прогон (минимальный)

```
/design-consultation   → система + превью
/design-shotgun        → варианты + доска
/plan-design-review    → добор решений в план
… код …
/design-review         → полировка
```

### Как это легло бы на наш проект

- **Шаг 1 `/design-consultation`** — вместо ручного брифа сам вывел бы палитру/шрифты
  и дал font+color превью. Бриф-ДНК из §1 скармливаешь ему как вводную.
- **Шаг 2 `/design-shotgun`** — вместо ручного `/logo` (4 кандидата) и трёх `data-dir`
  направлений: доска сравнения + структурный фидбэк.
- **Шаг 4 `/plan-design-review`** — поймал бы заранее то, что мы фиксили постфактум
  в `/design-review` (focus-visible, reduced-motion, дубли SVG id, тач-таргеты).
- **Шаг 6 `/design-review`** — как и было: дал B+ / AI-slop A.
